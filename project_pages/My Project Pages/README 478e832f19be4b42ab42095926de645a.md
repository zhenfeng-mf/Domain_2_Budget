## 3. Setup

```bash
git clone <repo>
cd <repo>
docker compose up --build
# then
docker compose run --rm web bin/rails db:prepare db:seed
```

App runs at `http://localhost:3000`.

**Requirements:** Docker only. Rails 8, MySQL 9, and all dependencies live in the container.

### Local development without Docker

Tailwind runs as a separate watch process, so start the app with `bin/dev` rather than `bin/rails server` — otherwise CSS changes will not rebuild.

```bash
gem install foreman   # not in the Gemfile by design; local convenience only
bin/dev
```

If `bin/dev` reports `foreman: not found` immediately after installing, refresh your Ruby manager's shims with `rbenv rehash` or `asdf reshim ruby`.

Equivalent without foreman, in two terminals:

```bash
bin/rails tailwindcss:watch
bin/rails server
```

In Docker and in production, CSS is built once at image build time with `bin/rails tailwindcss:build`; foreman is not involved.

## 5. Seed data

Seeds are a UX feature, not an afterthought — a reviewer should be able to hit the budget cap in one click.

- Two members and one approver
- A few categories
- Budgets across two or three months
- Expenses in every state: 下書き / 申請済み / 承認済み / 却下
- **One budget that is nearly exhausted**, so the cap can be triggered immediately
