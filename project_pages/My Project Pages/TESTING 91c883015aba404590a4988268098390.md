## The 5 things that must never break

| # | Must never break | Why it matters | How it is tested | State |
| --- | --- | --- | --- | --- |
| 1 | The approved total can never exceed the budget — **even under concurrent approvals** | The entire promise of the product. A single overspend destroys trust in the numbers | two-simultaneous-approvals test; total must stay ≤ budget | ⬜ |
| 2 | A member cannot read or modify another member's expense | Money data; an IDOR here is a real security failure | authorization tests hitting controllers directly with a foreign ID | ⬜ |
| 3 | An expense cannot be approved twice, or approved from 下書き | Double-counting silently corrupts the used amount | state transition tests for every illegal edge | ⬜ |
| 4 | An expense is always charged to the month of its 利用日 | Month-boundary misattribution is silent and hard to notice | boundary tests: last day and first day of a month | ⬜ |
| 5 | A budget cannot be lowered below the approved total | Would create a negative remaining balance out of nowhere | validation test at exactly the approved total, and one yen below | ⬜ |

## Test inventory

### Model / unit

- [ ]  Unique index on `(year_month, category_id)` actually raises at the DB level
- [ ]  `CHECK (amount >= 1)` actually raises at the DB level
- [ ]  Amount validation: 0, negative, `100.5`, empty, non-numeric, huge
- [ ]  Amount of exactly 1 is accepted
- [ ]  Month bucketing for the first and last day of a month

### Concurrency — highest value test in the project

- [ ]  Two approvals that individually fit but together exceed the budget → exactly one succeeds, total never exceeds
- [ ]  Approval that exactly hits the budget succeeds; the next yen is refused

### Authorization

- [ ]  Member A cannot edit or delete member B's draft (by ID in the URL)
- [ ]  A member cannot set a budget
- [ ]  A member cannot approve or reject

### State transitions

- [ ]  Cannot approve a 下書き
- [ ]  Cannot approve twice
- [ ]  Cannot reject an already-approved expense
- [ ]  Submitting the same draft twice is a no-op or refused

### Request / system

- [ ]  Happy path end to end: draft → submit → approve, remaining budget updates
- [ ]  Blocked approval shows an actionable message stating how much is actually left
